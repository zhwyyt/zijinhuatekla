# 分段 BOX 主体导致牛腿归零的回归修复

## 问题与证据

用户反馈 GKZ 牛腿数量不对。979 装配报告内 16 个 GKZ 全部为 0，旧同实例结果为 2～8；已验收案例中 T3-5GKZ-5 应为 4，T3-5GKZ-7 应为 2。问题不在实例匹配：此前身份修复已保证按装配 ID 消费正确快照。

新分组跨度主轴覆盖约 11m 的组合体，单块壁板约 3m。旧主壁板种子过滤要求单板跨度 ≥ 整根轴长的 45%，因此候选全被过滤。member 截面采样在长轴上均为异常，聚合 wall/flange/web 角色也为空，无法兜底，牛腿识别丢失主体。根因属于已导出特征的消费/筛选策略不适配分段主体；不重算或回退已验收主轴。

仅按局部候选跨度放行不充分：只取单个最大面积截面的种子，会漏掉其它段的壁板；漏掉的主体进入附属件聚类，导致假牛腿。局部跨度 + 多截面外壁种子并集的诊断实验恢复了新旧 16 个实例的原牛腿数。原始、单改长度和完整方案证据在 `outputs/gkz-corbel-investigation-20261010/`。

## 修复范围

- 主壁板种子的相对长度基准限制在可用纵向壁板候选的最大段跨度；保留 800mm 最小跨度、45% 相对限制和法向投影过滤。
- 每个导出的截面仍用现有多边形外边界验证；取所有有效截面外壁零件的并集，不能只选最大截面。
- 新分段策略只用于板件主体；当主件明确 `isPlateLike=false` 时，保留原整轴长度过滤和最大截面种子。不能用型钢主体上的短附属板重新定义主体。
- 不用构件号/零件号判定主体或强写牛腿数量，不回填历史 ID，不改变牛腿计数/聚类评分或已验收主轴算法。
- 改动限于共享 BOX 壁板分组入口，批量复杂度、零件特征、单构件流水线共同消费；出图 worktree 独立不动。

## Acceptance Criteria

- 匿名多段 BOX 的约 11m 主轴保持不变，约 3m 的壁板仍由截面证据确认为主体。
- 不同截面上的壁板都保留；短连接板、内板和没有截面支撑的孤立候选不能升级为外壁。
- 冻结的新导出案例经原正式入口恢复已验收的 4 个/2 个牛腿，包含 2 个型钢牛腿 + 2 个板组牛腿的情况。
- 新选择集 16 个 GKZ 与原同实例牛腿数一致；新旧包分别验证，不依靠旧轴/旧角色表输入。
- 牛腿单元的型钢脊柱 ID / 板组 ID 与原基线一致，不只核对总数量；其余 963 个装配的报告字段保持一致，原生型钢主体不得被统计为牛腿。
- 979 装配完整主线重跑，跨表行数/数量不丢失；与上一版逐字段核查影响，角色规则和主轴输入不变。

## Verification Plan

1. 增加匿名长轴分段、多个截面、短斜过渡板负例，以及从新导出裁剪的牛腿端到端失败用例；修复前确认失败。
2. 修改共享壁板种子消费；运行相关回归和全量单元测试，完整日志落盘。
3. 用已有新导出重跑 979 装配，不再次调用 Tekla，不覆盖此前文件。
4. 对比新旧 16 个 GKZ 数量及牛腿单元明细，记录其它字段影响；明确未经新人工确认的部分。
5. 写验证记录、STATUS/TASKLIST 和抽象复盘；CCG 检查后仅提交相关源码/测试/文档。

## 实施中发现的边界

第一次无范围保护的实现虽恢复 16 个 GKZ，却使 3 个 GKL 由 0 变为 1：短附属板成为 BOX 种子，H 钢主体进入外伸簇。逐字段对比拦截了该误报，最终用主件的板件事实限制范围，不使用 GKL/GKZ 编号作为修复判据。导出中的 `hBeamSectionEvidence.source` 在部分板件主体也标为 `directHProfileSectionFrame.v1`，不能只依赖该 source 判定原生型钢。

冻结样例裁剪最初遗漏外部 `boltHoles` 连接端点，导致独立回归归零；补回原始证据并匿名化端点后，原代码仍为 0，最终代码恢复 4 / 2。增加缺少外部证据时保持 0 的负例，防止测试靠预设数量通过。

最终验证结果见 [GKZ 牛腿回归记录](../verification/2026-10-10-gkz-corbel-regression.md)。
