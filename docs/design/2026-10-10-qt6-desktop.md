# Qt6 桌面交付

## 范围与方案

用户要求可直接启动的 exe：模块1在 Tekla 打开模型并选好构件后，选择保存目录、点击开始导出；模块2选择已导出的数据集和结果目录、点击开始生成识别结果；两模块有日志与错误提示。

替换现有 Tkinter 为 PySide6/Qt6，CLI `gui` 共用同一界面。保留已经验收的主轴和当前主材识别规则，不改出图 worktree。模块1调用现有 .NET 4.8 / Tekla 2017 Runner；程序不负责在 Tekla 中切换模型。导出器随包携带，开发环境仍可指定 Runner。选择的目录下每次建立唯一的数据集子目录，防止混入旧导出。

两个页签共用执行状态、日志和进度。QThread 执行任务，通过信号更新界面；运行时锁定两模块输入和按钮，避免重复任务和中途修改参数，关闭运行中窗口时提示等待任务结束。模块1逐行显示 Runner 输出，模块2逐装配显示处理进度，异常堆栈保存到所选输出目录的 logs；输入/目录错误也给出可读提示。模块1成功后自动填入模块2的数据源。部分构件失败、主轴复核和普通成功分别提示。

PyInstaller 生成 Windows 单文件 exe，内置 Python、Qt6、识别依赖和 Runner 三个运行文件；不打包 Tekla 模型、cache、Excel 或商业 Tekla API DLL。在线导出要求目标电脑已安装 Tekla 2017、.NET Framework 4.8 并打开模型，离线模块无需 Tekla/Python。保存可重复构建脚本及交付说明。

## Acceptance Criteria

- exe 启动显示 Qt6 两模块，中文、路径浏览、日志、运行状态可用，无需单独装 Python。
- 模块1读取当前选择集，保存到用户指定目录下的独立数据集；实时日志可见，空选择/导出器失败不假报成功。
- 模块2接收数据集目录或 bundle 文件，项目名/区域和结果目录可指定，输出正式三主表，继承当前算法结果。
- 任务中窗口保持响应，两按钮防重复；失败后可继续操作，日志有详细原因与文件路径。
- 打包版实际启动，并使用已有数据集完成离线分析；与同版正式入口结果核对。在线真实全量导出若未执行，必须如实记录，不冒充验收。

## Verification Plan

1. 回归导出器参数、非零退出、超时、实时输出、空选择和空路径；验证模块输入和任务日志。
2. Qt 测试覆盖两模块任务信号、失败恢复、警告、路径传递及运行时锁定。
3. 完整单元测试，构建 exe 后启动并操作；离线读取已导出的 979 装配包生成结果并核对三表。
4. 检查发行包不含业务输入，记录版本、大小、SHA256、运行前提及未验证边界。
5. 更新 README/STATUS/TASKLIST，CCG 暂存检查后提交推送代码与文档，二进制保存在本地 dist。

## 实现与验收补充

打包时隔离子进程 PATH，避免误收构建机其它工具的同名 DLL。曾误收 Poppler 的 icuuc.dll，使 QtCore 加载失败；修复后构建脚本必须启动实际 exe、创建 Windows Qt 窗口并检查结果，才生成发行清单。外部 Runner 使用参数数组启动，不经过 shell；仅执行内置或用户在高级选项指定的程序，路径不作为命令文本拼接。数据集按唯一目录保存，业务输入不打包上传。
